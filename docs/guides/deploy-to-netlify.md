# Deploy a Daffodil storefront to Netlify

This tutorial takes you from a new Angular project to the Daffodil commerce demo running on Netlify with server-side rendering (SSR). It uses the demo's in-memory driver by default, so you do not need a Magento or Shopify backend to complete it.

Netlify hosts the frontend and its rendering handler. If you later connect a commerce backend, that backend runs separately.

## Prerequisites

- Node.js 24.13.1 or later within the Node 24 release line, with npm 11.
- Git and a repository on a Git provider supported by Netlify, such as GitHub.
- A Netlify account with permission to import that repository.

The commands below use Angular CLI **21.2.31**, Daffodil **0.94.1**, and Netlify Angular Runtime **4.0.0**. Daffodil 0.94.1 requires Angular 21. Keep these versions together for this walkthrough; installing the latest release of each independently can introduce incompatible dependencies. See [Angular's version compatibility table](https://angular.dev/reference/versions) when choosing another combination.

## 1. Create an Angular application

From the directory where you keep your projects, run:

```bash
npx @angular/cli@21.2.31 new daffodil-netlify --style=scss --routing=true --ssr=true --zoneless=false --package-manager=npm --defaults
cd daffodil-netlify
```

This creates a standalone Angular application with routing and SSR. This example explicitly uses Zone.js change detection.

Create a `.nvmrc` file beside `package.json` containing:

```text
24
```

Netlify can use this file to select the build's Node version. Commit it along with `package-lock.json` so local and hosted builds use the intended runtime and resolved dependencies. See [Netlify's dependency configuration](https://docs.netlify.com/build/configure-builds/manage-dependencies/).

## 2. Add the Daffodil demo

```bash
npx ng add @daffodil/commerce@0.94.1 --driver=demo --is-new-project --skip-confirmation
```

The generator installs Daffodil and creates the demo storefront, including navigation, products, and the driver-switching tools. Leave the initial driver set to **In-Memory Driver** for this walkthrough. Selecting a remote driver introduces that service's configuration and availability requirements.

Start the application:

```bash
npm start
```

Open `http://localhost:4200`. Confirm that the Daffodil homepage and sample products appear, then stop the server with `Ctrl+C`.

## 3. Configure server-side rendering for Netlify

Install the adapter:

```bash
npm install --save-dev --save-exact @netlify/angular-runtime@4.0.0
```

Replace `src/server.ts` with:

```typescript
import { AngularAppEngine, createRequestHandler } from '@angular/ssr';
import {
  getAllowedHosts,
  getContext,
  getTrustProxyHeaders,
} from '@netlify/angular-runtime/app-engine.js';

const angularAppEngine = new AngularAppEngine({
  allowedHosts: getAllowedHosts(),
  trustProxyHeaders: getTrustProxyHeaders(),
});

export async function netlifyAppEngineHandler(request: Request): Promise<Response> {
  const response = await angularAppEngine.handle(request, getContext());
  return response ?? new Response('Not found', { status: 404 });
}

export const reqHandler = createRequestHandler(netlifyAppEngineHandler);
```

This follows the [Netlify Angular Runtime handler](https://github.com/netlify/framework-adapters/tree/main/packages/angular-runtime#customizing-request-handling) for Angular SSR 21.2.9 and later. It uses the hosts supplied by Netlify for production and preview deployments. Do not replace the allowed-host configuration with a wildcard.

Netlify runs this request handler as an Edge Function. The generated Express listener is no longer needed, and the generated `serve:ssr:daffodil-netlify` script is no longer a way to start this handler. Continue to use `npm start` for Angular development.

Replace `src/app/app.routes.server.ts` with:

```typescript
import { RenderMode, ServerRoute } from '@angular/ssr';

export const serverRoutes: ServerRoute[] = [
  { path: '**', renderMode: RenderMode.Server },
];
```

This renders routes on request instead of trying to discover and prerender the demo's dynamic product URLs during the build. Keep the generated `provideServerRendering(withRoutes(serverRoutes))` registration in `app.config.server.ts`.

In `src/app/app.config.ts`, add `withFetch` to the existing HTTP import and update the existing provider:

```typescript
import { provideHttpClient, withFetch } from '@angular/common/http';

// Inside the existing providers array:
provideHttpClient(withFetch()),
```

Keep the other providers generated by Daffodil. This enables Angular's fetch-based HTTP client for SSR.

## 4. Check the production build

The multi-driver demo is larger than Angular's default starter budget. In `angular.json`, under `projects.daffodil-netlify.architect.build.configurations.production.budgets`, update only the entry with `"type": "initial"`:

```json
{
  "type": "initial",
  "maximumWarning": "1.2MB",
  "maximumError": "1.5MB"
}
```

Retain the separate component-style budget. These limits accommodate this demo's approximately 1.09 MB initial bundle; review the budget again when replacing demo tooling with your storefront's features.

Build the application:

```bash
npm run build
```

The build should produce browser assets in `dist/daffodil-netlify/browser` and server output in `dist/daffodil-netlify/server`. With every route set to `RenderMode.Server`, `Prerendered 0 static routes` is expected.

The adapter may report missing Netlify environment variables during a plain local build. Netlify supplies these when building the deployed site. Compilation and bundle-budget errors still need to be fixed before continuing.

## 5. Add the Netlify build configuration

Create `netlify.toml` beside `package.json`:

```toml
[build]
  command = "npm run build"
  publish = "dist/daffodil-netlify/browser"

[[plugins]]
  package = "@netlify/angular-runtime"
```

The publish directory contains browser assets; the adapter packages the server output separately. Uploading only the browser directory through a manual drag-and-drop deploy does not deploy this SSR application.

Keep the SSR handler in charge of application routes. A catch-all `/* /index.html 200` rewrite is for a client-rendered SPA and is not needed here. Netlify's Angular SSR handler runs before redirect rules. See [Angular on Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/angular/).

## 6. Import the repository into Netlify

Commit the application, including `package-lock.json`, `.nvmrc`, and `netlify.toml`, and push it to your Git provider. Do not commit `node_modules` or `dist`.

In Netlify:

1. Choose the option to add a project by importing an existing Git repository.
2. Connect your Git provider and select the repository.
3. Select the branch you want Netlify to deploy, such as `main`.
4. Check the following build settings, then deploy.

| Setting | Value |
| --- | --- |
| Base directory | Leave unset: the app is at the repository root |
| Build command | `npm run build` |
| Publish directory | `dist/daffodil-netlify/browser` |
| Node version | Node 24, selected by `.nvmrc` |

No application secrets are required for the default in-memory demo. Review the deploy log to confirm that Netlify loads `@netlify/angular-runtime` and completes the application build and Edge Function packaging.

When the deploy is published, open the assigned `https://<project-name>.netlify.app` address. Subsequent pushes to the selected branch trigger another build.

## 7. Verify the deployed storefront

- Open the homepage and confirm that navigation, sample products, and images load.
- Open a product from the homepage and confirm that client-side navigation works. Refresh the homepage to check that a fresh server request renders successfully.
- Use **View Page Source** on the homepage and look for the visible heading, “Build a storefront that connects to”. Finding that content in the response confirms that the server rendered it; the browser's Elements panel alone does not prove SSR.
- Check the browser console and Network panel for failed JavaScript, image, or API requests.
- Open a nonexistent path and confirm that the application displays its not-found page. Check the response status separately if you require an HTTP 404.

The in-memory driver generates temporary sample products and URLs. In this version of the demo, a copied product URL can return the application's not-found page after a full reload because the new application instance has different sample data. That result is not, by itself, evidence of a broken Netlify deployment. After connecting a backend with stable product URLs, also verify that a product URL opens directly in a new tab and survives a refresh.

This walkthrough does not configure persistent carts, payments, or a production commerce backend.

## Applying this setup to an existing storefront

### An application in a subdirectory

Breeze keeps its Angular application in `frontend/dai-builder`. For an independently installed application with that layout, set Netlify's **base directory** to `frontend/dai-builder`, keep the app's `netlify.toml` there, and use `dist/dai-builder/browser` as the publish directory. Paths are relative to the base directory, so do not repeat `frontend/dai-builder` in the publish path.

This assumes the application has its own package manifest and lockfile. A workspace that installs dependencies at the repository root may need different base and package directories; follow [Netlify's monorepo configuration](https://docs.netlify.com/build/configure-builds/monorepos/).

### Connecting a commerce backend

Angular's development proxy configuration is used by `ng serve`; it does not configure the deployed site. If your browser requests an application-relative URL such as `/graphql`, provide a deployed handler for it or configure the driver to use the backend's absolute HTTPS URL with the required CORS settings.

Breeze handles its backend proxy routes in `src/server.ts`, before calling `AngularAppEngine.handle`. A `/graphql` redirect in `netlify.toml` alone cannot be relied on when the SSR Edge Function handles the request first. A common symptom is an API request returning HTML instead of JSON.

Any proxy you add should target a fixed, trusted backend and deliberately handle methods, authentication, cookies, and caching. The public demo does not need this proxy. Do not copy Breeze-specific service URLs or credentials into a new project.

### Configuration and caching

Netlify build variables do not automatically become Angular browser configuration. Add an explicit build-time configuration step if your application needs one, and treat anything bundled into browser JavaScript as public. Configure server-only secrets through Netlify with the appropriate runtime scope. See [Netlify's environment-variable documentation](https://docs.netlify.com/build/configure-builds/environment-variables/).

Start without shared caching for personalized responses. Breeze adds a separate policy for eligible anonymous pages; it is not required to deploy Daffodil. Review cart, account, authorization, and cookie behavior before introducing shared HTML caching.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Dependency installation reports a peer conflict | Use Angular 21 with Daffodil 0.94.1, and commit the resulting lockfile. Avoid bypassing the conflict with `--force`. |
| Node engine requirements are not met | Use Node 24.13.1 or later within Node 24 locally and on Netlify. Check for an older `.node-version` overriding `.nvmrc`. |
| Build fails on the initial bundle budget | Apply the demo budget in step 4; inspect the size before increasing it again. |
| Publish directory does not exist | Confirm the Angular project name, output path, and Netlify base directory. |
| A demo product disappears after refresh | The in-memory driver regenerates sample data. Test stable product links after connecting a persistent backend. |
| A real backend's product links work only after navigating from the homepage | Check that SSR is enabled, the adapter ran, and the server handler and routes match step 3; verify that SSR can reach the backend. |
| `@netlify/angular-runtime/context.mjs` cannot be resolved | That import belongs to the older adapter used by Breeze. Runtime 4 uses `@netlify/angular-runtime/app-engine.js` as shown above. |
| Requests are rejected by host validation | Check Netlify's deployment URL variables and the adapter's allowed-host setup. Do not disable validation globally. |
| A backend API returns HTML | Check whether the request reached Angular's page handler instead of a backend proxy. |
| Remote images fail after enabling Netlify Image CDN | Configure the allowed image origins in `netlify.toml`; see [Netlify's Angular image guidance](https://docs.netlify.com/build/frameworks/framework-setup-guides/angular/#netlify-image-cdn). |
